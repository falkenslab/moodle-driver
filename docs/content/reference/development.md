# Development

How to work on the driver itself. The repository's `CLAUDE.md` and `.minispec/` hold the conventions and the design.

## Commands

```bash
npm install
npm run typecheck
npm run lint
npm run test:docker   # every test, in Docker
npm run build         # dist/, with declarations
npm run docs:install  # the documentation site's dependencies
npm run docs:start    # the site on localhost, live
npm run docs:build    # the site, as published
```

## Tests run in Docker

The tests launch real browsers against the fake Moodle, one file at a time. They run only in Docker (`scripts/in-docker.mjs`, Playwright's image), never on the developer's desktop, where they'd open windows. One file:

```bash
MSYS_NO_PATHCONV=1 node scripts/in-docker.mjs npx tsx --test test/moodle/quiz.test.ts
```

(`MSYS_NO_PATHCONV=1` is for Git Bash on Windows.) The container keeps its own `node_modules` in a volume, reinstalled when the lock file changes.

## A real Moodle

The fake Moodle stands for what the driver reads, but only a real site confirms it. The Moodle sandbox (a sibling repository) runs Moodle 5.2 in Docker with a demo course, teacher and students. When it's running, `scripts/in-docker.mjs` joins its network and forwards `localhost:8080` inside the container, so a scratch script can call the driver against it headless, on profiles logged in once.

## Conventions

- Everything in English: code, comments, docs, commit messages.
- A function takes the browser context and the site, then ids, then options; it returns plain data.
- Every page a function reads is opened with `openSitePage()`; services go through `callService()`.
- Read Moodle by structure (ids, data attributes, field names, body ids, URLs), never by visible text.
- Page code with helper functions goes through `inPage()`.
- Errors a program can act on get their own class, with messages in Moodle's terms.
- The library never prints, reads no environment variables, and knows nothing of its consumers.
- Every public function declares its data categories in `src/categories.ts`; a test enforces it.
- Every function gets a doc comment: the [API reference](https://falkenslab.github.io/moodle-driver/docs/api) is generated from them.

## Documentation

This site lives in `docs/` (Docusaurus). Guides are Markdown under `docs/content/`, one line per paragraph; the API reference is generated by TypeDoc from `src/index.ts` and `src/testing/index.ts` on every build. A change that a program using the driver would notice updates the guide that describes it in the same commit. The site is published to GitHub Pages on every push to `main`.
